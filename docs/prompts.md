# پرامپت‌ها

هر پرامپت یک **رکورد دیتابیس** با نسخه است؛ هیچ پرامپتی در کد نیست. ایجنت فقط کلید
(`system_prompt_key`) را نگه می‌دارد، پس تغییر متن، ایجنت را لمس نمی‌کند.

## ۱) قواعد حل و اولویت

```
پرامپت سازمانی همان key  ──(اولویت)──▶  پرامپت سراسری (org_id = NULL)
                 ▼                              ▼
           رندر با متغیرها  ◀── مقادیر: org.*، agent.*، today_jalali، values ورودی
```

- پرامپت **سراسری فقط‌خواندنی** است (403 `prompt.global_readonly`)؛ سازمان با ساخت
  نسخه‌ی خودش، آن را شخصی‌سازی می‌کند و آپدیت محصول، شخصی‌سازی را از بین نمی‌برد.
- ویرایش = نسخه‌ی جدید (`current_version + 1`)؛ تاریخچه حفظ می‌شود.
- `rollback` نسخه‌ی قدیم را **حذف نمی‌کند**؛ یک نسخه‌ی جدید با متن قدیم می‌سازد
  (یادداشت: «بازگشت به نسخه N»).
- رندر سخت‌گیرانه: متغیر نامعلوم → `422 prompt.missing_variables` با فهرست `missing`.
  (پیش‌نمایش در پنل با `strict=false` اجرا می‌شود تا ادیتور نشکند.)

## ۲) متغیرهای آماده

| متغیر | منبع |
|---|---|
| `{{org.name}}` / `{{org.timezone}}` | سازمان جاری |
| `{{agent.name}}` / `{{agent.role}}` | ایجنت در حال اجرا |
| `{{today_jalali}}` | تاریخ امروز، جلالی، ارقام فارسی («۱۸ آبان ۱۴۰۵») |
| `{{today}}` | تاریخ امروز جلالی به شکل `۱۴۰۵/۰۸/۱۸` |
| هر کلید دیگر | از `values` در پیش‌نمایش یا ورودی وظیفه |

## ۳) پرامپت‌های پیش‌فرض (۱۳ مورد، همه فارسی)

| key | نوع | نقش |
|---|---|---|
| `agent.system.default` | agent.system | شخصیت پایه‌ی هر ایجنت (قواعد لحن، تأیید، محرمانگی) |
| `agent.system.accountant` | agent.system | ایجنت حسابدار (منبع‌دار بودن اعداد، تأیید سند) |
| `agent.system.sales` | agent.system | ایجنت فروشنده (لحن، ممنوعیت تخفیف بدون تأیید) |
| `agent.system.receptionist` | agent.system | منشی/پاسخگو (پاسخ کوتاه، شماره پیگیری، محرمانگی) |
| `agent.task.daily_sales_report` | agent.task | گزارش روزانه فروش با ورودی `data` |
| `guard_input.default` | guard_input | تشخیص تزریق پرامپت و درخواست داده‌ی محرمانه → JSON |
| `guard_output.default` | guard_output | پاک‌سازی نشت کلید/کارت/کد ملی و لحن نامناسب |
| `planner.default` | planner | برنامه‌ریزی گام‌به‌گام با ابزارها |
| `summarizer.default` | summarizer | خلاصه‌ی گفتگو + کارهای باقی‌مانده |
| `memory_extract.default` | memory_extract | استخراج واقعیت‌های پایدار مشتری |
| `tool_policy.default` | tool_policy | تصمیم اجازه‌ی ابزار با JSON |
| `voice.persona.default` | voice.persona | شخصیت منشی تلفنی (جمله کوتاه، barge-in) |
| `rag.answer.default` | rag.answer | پاسخ فقط بر اساس متن دانش سازمان |

نمونه (`agent.system.accountant`):

```text
تو «{{agent.name}}»، حسابدار رسمی «{{org.name}}» هستی. امروز {{today_jalali}} است.
وظایف: ثبت و طبقه‌بندی اسناد، تطبیق بانکی، تهیه صورت‌حساب و گزارش ماهانه،
کنترل مالیات بر ارزش افزوده.
قواعد:
- هر عدد را با واحد و منبع آن گزارش کن؛ عدد بدون منبع ننویس.
- قبل از ثبت سند، خلاصه‌ی سند را برای تأیید نشان بده.
...
```

## ۴) کار با API

```powershell
# ساخت نسخه‌ی سازمانی از یک پرامپت سراسری
POST /v1/prompts
{"key":"agent.system.accountant","title_fa":"حسابدار سازمان ما",
 "kind":"agent.system","publish":true,
 "template":"تو «{{agent.name}}» حسابدار «{{org.name}}» هستی. امروز {{today_jalali}}.\nهمیشه اول مانده‌ی حساب‌ها را نشان بده."}

# ویرایش (نسخه‌ی ۲)
PUT /v1/prompts/{id} {"template":"…","note":"لحن سخت‌گیرانه","publish":true}

# بازگشت به نسخه‌ی ۱ (نسخه‌ی ۳ ساخته می‌شود)
POST /v1/prompts/{id}/rollback {"version":1}

# دیدن پرامپت مؤثر یک ایجنت (همان چیزی که به مدل می‌رود)
GET /v1/agents/{id}/prompt
```

## ۵) قالب پیشنهادی نوشتن پرامپت فارسی

```text
۱) نقش و مالکیت:  تو «…» هستی؛ … سازمان «…».
۲) زمینه:         امروز {{today_jalali}}؛ منطقه‌زمانی …؛ واحد پول تومان.
۳) وظایف:         ۱) … ۲) … ۳) …
۴) قواعد سخت:     - عدد بدون منبع ننویس. - قبل از کار حساس تأیید بگیر.
۵) قالب خروجی:    جدول/فهرست، ارقام فارسی، مبالغ با جداکننده.
۶) ممنوعیت‌ها:     افشای کلید/رمز، اقدام بدون تأیید، پاسخ خارج از دانش سازمان.
```

## ۶) وضعیت پیاده‌سازی

| قابلیت | وضعیت |
|---|---|
| نسخه‌بندی + انتشار + بازگشت | ✅ |
| اولویت سازمان بر سراسری | ✅ |
| رندر متغیر با `missing` | ✅ |
| پیش‌نمایش با `values` و `agent_id` | ✅ |
| `prompt_examples` (few-shot) | ⏳ جدول آماده، API ندارد |
| A/B بین دو نسخه | ⏳ |
| استفاده‌ی خودکار از `guard_input`/`guard_output` در اجرا | ⏳ (پرامپت‌ها seed شده‌اند، در حلقه فراخوانی نمی‌شوند) |
| `voice.persona` در تماس | ⏳ (ماژول صدا در roadmap) |
