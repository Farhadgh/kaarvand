# برنامه‌ها (App Catalog)

بخش «برنامه‌ها» در پنل یک **فروشگاه اتصال** است: واتساپ، تلگرام، اینستاگرام، ایکس، فیسبوک،
لینکدین، اسلک، دیسکورد، بله، ایتا، روبیکا، آفیس (اکسل/ورد/آوت‌لوک)، گوگل (شیت/تقویم/جیمیل)،
نوشن، ترلو، گیت‌هاب، زوم و برنامه‌های نصب‌شده روی رایانه‌ی مشتری.

هر ردیف کاتالوگ یک **قالب** است، نه یک اتصال زنده. با «اتصال»، قالب در یک ابزار سازمانی
(`tools`) کپی می‌شود و به ایجنت می‌چسبد؛ بنابراین موتور اجرا، ماتریس ریسک، تأیید انسانی و
دفتر مصرف دقیقاً مثل بقیه‌ی ابزارها کار می‌کنند و **هیچ کد تازه‌ای** برای اضافه‌کردن برنامه لازم نیست.

## ۱) دو نوع برنامه

| نوع | `runtime` | اجرا در | چه چیزی از شما می‌خواهد |
|---|---|---|---|
| ابری (HTTP) | `cloud` | سرور، با `httpx` | توکن + شناسه‌هایی مثل `phone_number_id` (مقصد پیام، ورودی مدل است) |
| روی دستگاه | `desktop` | رایانه‌ی مشتری، با کانکتور | انتخاب دستگاه آنلاین + مسیرهای مجاز |

برنامه‌ی دسکتاپ یک ابزار `kind=connector` است و اسکریپت اقدامش (مثل `office.open`,
`app.launch`, `keyboard.type`) روی دستگاه اجرا می‌شود.

## ۲) مسیر کاربر در پنل

1. منوی **برنامه‌ها** (`/apps`) → کارت با لوگوی برند.
2. **اتصال** → ویزارد چهار بخشی:
   - انتخاب ایجنت،
   - (برای دسکتاپ) انتخاب دستگاه،
   - ورود اعتبارنامه (فیلد password، فقط نوشتن) و شناسه‌های لازم،
   - سطح دسترسی: `خودکار` / `با تأیید` (پیش‌فرض) / `ممنوع`.
3. بعد از اتصال، برنامه در صفحه‌ی همان ایجنت زیر «برنامه‌ها و شبکه‌ها» دیده می‌شود و مدل
   می‌تواند آن را صدا بزند (فقط با تأیید، اگر `confirm` باشد).
4. **آزمون اتصال**: در `/tools` دکمه‌ی «تست ابزار» با آرگومان‌های نمونه
   (`{"chat_id": "...", "text": "سلام"}`) — سیاست تأیید دور زده می‌شود چون ادمین دستی اجرا می‌کند.
5. **قطع اتصال**: از کارت برنامه در صفحه‌ی ایجنت، یا `DELETE /v1/apps/{slug}/install?agent_id=…`.

## ۳) افزودن ابزار دلخواه

دو حالت، هر دو بدون کدنویسی:

- **HTTP سفارشی** — `method`, `url`, `allowed_domains`, `headers`, `body` با `{{متغیر}}`,
  `auth` (`none|bearer|header|query`), `timeout` و یک JSON Schema برای ورودی مدل.
- **اسکریپت روی دستگاه** — چیدن گام‌ها از کاتالوگ ۲۴ عملیات (بخش ۶).

در پنل: `/apps` → «+ افزودن ابزار من» یا کارت خط‌چین انتهای گرید. خروجی همان
`POST /v1/tools` است، پس ابزار بلافاصله در `/tools` هم دیده می‌شود.

## ۴) کاتالوگ پیش‌فرض

| slug | نام | نوع | ریسک |
|---|---|---|---|
| `telegram` | تلگرام (Bot API) | cloud | medium |
| `whatsapp` | واتساپ (Cloud API) | cloud | medium |
| `instagram` | اینستاگرام (Messaging API) | cloud | medium |
| `x` | ایکس/توییتر | cloud | high |
| `facebook_page` | فیسبوک (صفحه) | cloud | high |
| `linkedin` | لینکدین | cloud | high |
| `slack` | اسلک | cloud | medium |
| `discord` | دیسکورد (Webhook) | cloud | medium |
| `bale` / `eitaa` / `rubika` | پیام‌رسان‌های ایرانی | cloud | medium |
| `google_sheets` / `google_calendar` / `gmail` | گوگل | cloud | medium/high |
| `notion` / `trello` / `github` / `zoom` | بهره‌وری | cloud | medium |
| `excel` / `word` / `outlook` | آفیس روی دستگاه | desktop | medium/high |
| `telegram_desktop` / `whatsapp_desktop` / `chrome` / `softphone` | برنامه‌های ویندوز | desktop | medium/high |

> **واقع‌بینی:** «قالب آماده» یعنی مسیر و بدنه و اسکیما نوشته شده است؛ ولی هر سرویس
> اعتبارنامه‌ی خودش را می‌خواهد (توکن ربات، Permanent Token متا، اپ X، بازبینی لینکدین).
> این پیش‌نیازها در ویزارد، بالای فرم، برای هر برنامه نوشته شده‌اند (`setup_fa`).
> برای پیام‌رسان‌های ایرانی مسیرها بر اساس APIهای عمومی نوشته شده‌اند و اگر سرویس
> تغییر کند، فقط ردیف کاتالوگ (JSON) عوض می‌شود، نه کد.

## ۵) API

| متد | مسیر | نقش | کار |
|---|---|---|---|
| GET | `/v1/apps` | همه | کاتالوگ + شمارش «نصب‌شده/دستگاه‌های شناسایی‌شده» |
| GET | `/v1/apps/{slug}` | همه | جزئیات + `credentials` + قالب‌ها (برای ویزارد) |
| POST | `/v1/apps/{slug}/install` | owner/admin/operator | ساخت ابزار از قالب + اتصال به ایجنت |
| DELETE | `/v1/apps/{slug}/install?agent_id=` | owner/admin/operator | حذف اتصال و ابزار |
| GET | `/v1/devices/{id}/apps` | همه | برنامه‌های شناسایی‌شده روی دستگاه |
| POST | `/v1/devices/{id}/scan-apps` | owner/admin/operator | اسکن دستگاه از طریق کانکتور |
| PATCH | `/v1/devices/{id}/apps/{slug}` | owner/admin/operator | مجاز/غیرمجاز کردن برنامه روی دستگاه |
| POST | `/v1/tools/{id}/clone` | owner/admin/operator | کپی سازمانی از ابزار سراسری (برای ویرایش/توکن) |

```jsonc
POST /v1/apps/whatsapp/install
{
  "agent_id": "…",
  "permission_level": "confirm",
  "secret": "EAAG…",                       // توکن، رمزنگاری‌شده ذخیره می‌شود
  "variables": { "phone_number_id": "1234567890" },
  "device_id": null,
  "force": false
}
→ 201 {"tool_id": "…", "slug": "whatsapp.9f3a12cb", "permission_level": "confirm", "warnings": []}
```

**قواعد مهم:**
- `slug` ابزار ساخته‌شده = `<app>.<۸ کاراکتر اول شناسه‌ی ایجنت>` → نصب دوباره‌ی همان برنامه
  برای همان ایجنت، **به‌روزرسانی** است نه رکورد تکراری.
- فیلدهای غیرسرّی با `fill` در قالب Config جایگزین می‌شوند؛ `{{secret}}` دست‌نخورده می‌ماند
  تا در زمان اجرا با اعتبارنامه‌ی رمزگشایی‌شده پر شود.
- خطاها: `app.not_found`, `app.missing_secret`, `app.missing_field` (`params.field`),
  `app.device_required`, `app.device_offline`, `app.not_detected`, `app.scan_failed`,
  `app.not_installed`, `app.install_conflict`.

## ۶) اسکن برنامه‌های دستگاه

1. قاعده‌ی تشخیص در دیتابیس است (`app_catalog.detect` = `{exe, prog_id}`).
2. پنل → `/devices` → «اسکن برنامه‌ها» → `POST /v1/devices/{id}/scan-apps`.
3. سرور پیام `{type:"apps.scan", catalog:[{slug, exe, prog_id}]}` را روی WSS می‌فرستد.
4. کانکتور روی ویندوز: فرایندهای در حال اجرا (`psutil` یا `tasklist`)، وجود کلید
   `HKCR\<prog_id>`، و مسیر نصب در `Program Files` را بررسی می‌کند و
   `{type:"apps.result", call_id, ok, apps:[{slug, exe, prog_id, version}]}` برمی‌گرداند.
5. سرور خروجی را با `detect` تطبیق می‌دهد (exe یا prog_id)، در `device_tools` ذخیره می‌کند و
   فقط برنامه‌های **موجود در کاتالوگ** ثبت می‌شوند.
6. «مجاز کردن» (`is_granted`) لازم است تا هنگام نصب، هشدار `app_not_granted` نگیرید.

## ۷) ایمنی

- `app.launch` فقط با **slug برنامه** کار می‌کند، نه مسیر دلخواه؛ مدل نمی‌تواند فایل اجرایی
  انتخاب کند. کانکتور مسیر را از نقشه‌ی داخلی خودش پیدا می‌کند.
- `fs.*` و `office.open` همچنان داخل `devices.allowed_paths` (هم سرور، هم کانکتور).
- `shell.run` فقط با پیشوندهای مجاز (`--allow-cmd`)؛ برای برنامه‌های کاتالوگ اصلاً لازم نیست.
- ارسال پیام/نوشتن فایل → `risk=medium|high` و `approval_policy=confirm`؛ اجرا در
  `waiting_approval` پارک می‌شود و با تأیید انسان ادامه می‌یابد.
- اعتبارنامه با AES‑GCM و AAD `tool:<slug>` ذخیره می‌شود؛ در پاسخ API فقط
  `has_secret`/`secret_masked` برمی‌گردد. **slug را بعد از ساخت عوض نکنید** (رمزگشایی می‌شکند).
- هر اجرا در `tool_invocations` با `device_id` و `approved_by` ثبت می‌شود.

## ۸) محدودیت‌های شناخته‌شده (بدون تعارف)

1. **دریافت پیام ورودی نداریم**: این بخش فقط «ارسال/اقدام» است. پاسخ‌دادن خودکار به پیام‌های
   واتساپ/تلگرام نیازمند وبهوک ورودی و تریگر رویداد است (قدم بعدی).
2. در کلاینت مرجع، گام‌های `office.*`, `com.invoke`, `print`, `phone.dial` **شبیه‌سازی** می‌شوند؛
   `app.launch` با `shutil.which` واقعی است و `clipboard.*` با PowerShell کار می‌کند.
   کنترل واقعی فتوشاپ/اکسل با `pywin32` و UI Automation در گروه اختیاری `[connector]` انجام می‌شود.
3. هاب کانکتور درون‌پروسه است؛ با چند worker باید bus مشترک (Redis/NOTIFY) اضافه شود.
4. اسکن روی ماشین‌هایی که هیچ‌کدام از برنامه‌های کاتالوگ را ندارند، لیست خالی برمی‌گرداند —
   این خطا نیست.
5. نصب برنامه‌ی دسکتاپ بدون دستگاه آنلاین رد می‌شود (`app.device_offline`) حتی با `force=true`.
